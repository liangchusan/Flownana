# Flownana 产品文档

状态：当前产品事实来源
最近复核：2026-09-10（首页合并与个人信息菜单已本地实现，待发布）

本文档定义 Flownana 当前已经确认的产品行为。大型功能在开发前必须先更新
本文档并确认范围；符合既有规则的小功能可以直接开发。本文档只描述当前
状态，不维护流水账式变更记录，历史版本由 Git 保存。

## 1. 产品愿景与目标

Flownana 是一个 0→1 的 AI 媒体生成产品，当前重点是快速上线和验证付费
投放。用户应当能够通过提示词或参考素材，快速获得可长期保存的图片或视频。

当前目标：

- 把图片生成稳定性作为 MVP 第一优先级
- 在不过度增加复杂度的前提下提供有价值的图片和视频创作能力
- 让积分成本、处理状态、失败原因和退款结果清晰可见
- 把生成媒体保存为用户可长期管理的资产
- 保持获客和转化主漏斗可衡量

## 2. 当前范围

当前产品支持：

- 落地页和营销页面
- Google 登录
- 文生图和图生图
- 视频生成及模型特定的参考素材输入
- 图片和视频共用的 Create 工作台
- 生成历史和长期 Assets 资产库
- 积分、订阅、结账、账单和升级
- 结果预览、引用、下载、删除和从最近记录移除
- 核心 GA4 漏斗埋点

音乐生成已经下线。历史音频仍可查看、下载和删除，但不能重新生成。

## 3. 明确不做

- 用户可见的 Project 系统；Agent 独立会话已批准，见第 18 节
- 自主多步骤媒体编排
- 新音乐生成
- 资产批量操作
- 收藏功能
- 高级媒体编辑工具
- 自动把所有上传参考素材保存为 Asset
- 未单独批准的重型后台系统或大规模架构重构

## 4. 信息架构与路由

- `/`：唯一首页，承载原 Home 的主体和交互
- `/home`：下线，返回 404，不保留页面或重定向
- `/image`：图片优先的创作入口
- `/video`：视频优先的创作入口
- `/assets`：生成资产库
- `/ai-image`：永久重定向到 `/image`，兼容旧链接
- `/ai-video`：永久重定向到 `/video`，兼容旧链接
- `/generate`：通用创作入口；恢复上次的 Image/Video 选择并进入 `/image` 或
  `/video`，新用户默认 Video
- `/ai-music`：重定向到 `/image`
- `/pricing`：套餐和结账入口
- `/account/profile`：头像、显示名称、邮箱和删除账号
- `/account/billing`：当前套餐、积分、升级和账单管理
- `/design-system`：内部设计系统预览页，不允许搜索引擎索引

`/`、`/image`、`/video` 和 `/assets` 使用同一套响应式导航外壳；Home
保留现有首页主体内容。`/image` 和 `/video` 使用同一套创作工作台，显式路由
决定 Composer 类型。

### 4.1 首页合并与公共信息（已本地实现，待发布）

- 用户直接访问 `/` 即进入现有 Home；保留侧栏、展示卡片、创作输入、最近作品
  和既有交互，不重新设计 Home。未登录的最近作品区继续显示登录提示。
- 移除原营销首页的首屏视频、功能介绍、用户评价、FAQ 和最终 CTA；仅迁移公司
  页脚信息，不新增承载旧营销内容的页面。
- 未登录时在 Home 主内容滚动区域底部展示 Logo、公司介绍、Products、Pricing、
  Contact Us、Privacy Policy、Terms of Service 和版权信息；已登录时不展示页脚。
  Session 加载中避免闪现未登录页脚，登录及退出后显隐同步。
- 页脚使用与 Home 相适配的温暖浅色背景、文字和分隔线，不沿用黑色背景；桌面
  不覆盖侧栏，移动端纵向排列。其余页面页脚不在本次改色范围内。
- 站内 Home、返回首页和默认登录返回地址统一使用 `/`；有明确登录返回目标时
  保留该目标。旧 `/home` 返回 404，不做参数转发或兼容重定向。
- `/privacy-policy` 和 `/terms-of-service` 保留现有正文及简洁的 Logo／返回首页
  入口，移除原营销顶部导航和公司页脚；桌面、移动端一致。
- 个人信息菜单中的 Contact Us 使用现有 Contact 页的邮箱，通过
  `mailto:support@flownana.com` 唤起邮件程序。现有 `/contact` 页面保留。
- 本次不调整埋点，具体边界见第 12 节；不改变生成、计费、套餐或数据库规则。

## 5. 创作工作台

### 5.1 导航与布局

- 桌面端使用可折叠的 Home/Image/Video/Assets 侧栏、中央工作区和可选的右侧
  详情面板。
- 移动端使用导航触发器、抽屉侧栏、单列内容流、底部 Composer 和全屏详情页。
- 侧栏只提供 Home、Image、Video 和 Assets 四个主导航项；不显示 New Create，
  也不显示可点击的通用 Create 导航项。
- 四个导航项分别使用 `/`、`/image`、`/video` 和 `/assets`。选中状态、页面
  内容和地址必须一致；直接访问、刷新及浏览器前进/后退均恢复正确页面。
- 点击 Image 或 Video 时，Composer 立即切换到对应类型；Composer 内部的
  Image/Video 选择器也同步更新规范地址。
- 在 Image、Video 和 Assets 之间切换不得清空 Prompt、附件、媒体类型或生成参数，
  也不得取消仍在运行的生成任务。
- Create 是操作历史，不是用户可见的 Session 系统。
- 图片和视频共用按时间排序的 Create 操作历史；媒体筛选只属于 Assets。
- 内容流上方不显示多余的桌面标题栏。
- 左右侧栏的展开/收起按钮使用轻量细线面板图标：默认无可见边框或实心底色，
  Hover 仅显示安静的表面变化，同时保留足够点击区域和清晰的键盘焦点状态。
- 侧栏底部 Upgrade 与用户入口区域上方不显示分割线。

### 5.2 Prompt 与 Result 内容流

- 图片、视频和历史音频按时间顺序显示，最新内容在底部。
- 每个已提交 Prompt 右对齐显示，原始输入素材位于 Prompt 正上方。
- 一个 Prompt 对应一个 Result Block。
- 图片请求可在一个 Result Block 中包含 1–4 个独立计费输出；视频和历史
  音频保持单输出。
- 提交后立即显示生成中 Result Block。
- 活跃结果立即预留符合宽高比的媒体区域，并显示 Flownana 品牌图标在深蓝海面
  漂移的动画。
- 响应层级保持轻量、无边框：处理状态、分隔线、行内参数、媒体和操作。
- 首条记录、跨本地日期或间隔至少一小时时显示时间分隔；标签使用
  `Today`、`Yesterday` 或紧凑英文日期与本地时间。
- 活跃任务显示实时 `Processing` 计时；有可靠数据时，完成和失败任务显示
  `Processed in` 或 `Failed after`。
- 多图片输出以最慢一个输出的耗时作为整组耗时。

### 5.3 结果展示

- 生成媒体必须保留原始宽高比，不得为了方形封面裁切或拉伸。
- 桌面单个结果最大约 512px 宽、480px 高。
- 四张 9:16 图片在桌面单行四列、移动端两列展示。
- 视频默认静音，提供播放/暂停、进度、已播放/总时长和声音控制。
- 明确以 Sound Off 生成的视频，其声音控件保持禁用。
- 点击图片、视频或音频打开聚焦预览。

### 5.4 结果操作

- 每个成功输出右上角提供 Download、Reference 和 Delete；桌面 Hover 或
  键盘 Focus 时显示，触控设备始终显示。
- 不提供单独 Expand 操作；点击媒体本身进入预览。
- Reprompt 恢复可用的 Prompt、原始输入、模型、参数和输出数量，替换当前
  草稿但不会自动提交。
- Reference 把生成结果加入当前 Composer 草稿。
- Delete 从 Create 和 Assets 删除选中输出；整组无剩余输出时，Create 显示
  紧凑的已删除占位。
- 已被其他生成任务作为输入引用的媒体必须继续保留。
- More → Remove from recent 隐藏完整 Prompt 和 Result 记录，但成功媒体仍
  保留在 Assets。
- Reprompt、Details 和 More 位于结果下方的同一操作组。

### 5.5 Composer

- 底部 Composer 在模型选择器前提供一个 Image/Video 选择器。
- 有效提交开始后清空 Prompt 和附件，但保留媒体类型和生成参数。
- Image/Video 切换共用同一个附件草稿。
- 删除附件后不能通过切换媒体类型让它重新出现。
- 不兼容附件保持可见并标记为不支持，阻止生成并提供 Remove unsupported；
  切换模型时不得自动删除。
- Generate 操作显示预计消耗的总积分。
- 最多允许五个输出任务同时活跃；多图片请求的每个输出都计入限制。

## 6. 图片生成

每个 Prompt 支持生成 1–4 张图片。

| 模型 | 模式 | 输入 | 分辨率与平台积分 |
| --- | --- | --- | --- |
| GPT Image 2 | 文生图、图生图 | 最多 1 张图片 | 1K：2，2K：3，4K：5 |
| Nano Banana 2 | 文生图、图生图 | 最多 1 张图片 | 1K：2，2K：4，4K：5 |
| Qwen Image 3.0 Pro | 文生图、图生图 | 最多 3 张图片，每张 10 MB | 1K：2，2K：4 |

允许的图片比例为 `Auto`、`9:16`、`16:9`、`1:1`、`3:4`、`4:3`，
并遵守模型限制：

- GPT Image 2 只有 1K 支持 Auto，4K 不支持 1:1。
- Qwen Image 3.0 Pro 不支持 Auto，只提供 1K/2K。
- 其他在售图片模型继续使用现有 20 MB 客户端上传上限。

只有结果已经保存到 Flownana 自有存储后，任务才能被视为成功。存储失败
必须让任务失败并退款，不能静默保存短期 Provider URL。

## 7. 视频生成

视频请求每次生成一个输出。生成前必须显示已批准的模型积分价格。KIE 模型
通常按 KIE API 积分乘以 `0.2`，再将整次请求结果四舍五入为整数 Flownana
积分；单独批准的例外以代码和本文档为准。

| 模型 | 输出选项 | 已批准的参考输入 |
| --- | --- | --- |
| Gemini Omni Video | 720P/1080P/4K；4/6/8/10 秒；16:9 或 9:16 | 最多 7 张图片 |
| Wan 3.0 Video | 480P/720P/1080P；2–30 秒；标准比例；Sound On/Off | 当前 P0 最多 10 张图片、1 个视频和 1 个音频 |
| Seedance 2.0 Mini | 480P/720P；4–15 秒；Auto 和标准比例；Sound On/Off | 最多 9 张图片、3 个视频和 3 个音频 |
| MiniMax H3 | 720P/2K；4–15 秒 | 可选首帧和尾帧 |
| Grok Imagine Video 1.5 | 480P/720P；1–15 秒 | 必须且只能有 1 张图片 |
| HappyHorse 1.1 | 720P/1080P；3–15 秒 | 最多 1 张可选图片 |

用户可见比例只允许 `Auto`、`16:9`、`9:16`、`1:1`、`4:3`、
`3:4`、`21:9`；分辨率只允许 `Auto`、`480P`、`720P`、`1080P`、
`2K`、`4K`。界面只能显示当前模型真正支持的值。

模型特定规则：

- MiniMax、HappyHorse 和 Grok 的图生视频由输入图片决定比例。
- Seedance 和 Wan 把 Auto 映射为各自安全的自适应值。
- Gemini 始终发送其要求的 16:9 或 9:16。
- Wan 带参考视频时，输出最长 15 秒。
- Gemini 的源视频、上传音频和 Character ID 在定价和 Provider ID 方案获批
  前不进入 P0。
- 视频任务等待超过 45 分钟后标记超时并退款。
- 同一视频任务的成功与失败结算必须通过数据库事务争夺唯一终态；并发轮询不得
  重复退款、覆盖已成功任务或产生“成功且已退款”的状态。

## 8. Assets 与媒体生命周期

- Assets 是成功且未删除的生成输出平铺网格。
- 上传的参考素材不会自动加入 Assets。
- 筛选项：All、Images、Videos、Audio。
- 工具：Prompt 搜索和 Newest/Oldest 排序。
- Assets 支持预览、下载、删除和 Reference 回 Create。
- 生成中和失败任务只显示在 Create。
- 生成媒体和任务输入都登记为用户媒体资产，并通过 input/output 关系关联任务。
- 删除未被引用的生成输出时，同时删除自有存储对象和资产记录；仍被任务引用
  的媒体继续保留。
- 历史 Provider 媒体 URL 失效时，可以尝试刷新为新的可访问 URL。
- 新上传必须使用已登录用户的一次性预约：Token 最长有效 10 分钟，每用户每小时
  最多 60 个预约、24 小时预约总量最多 1 GB；单文件上限为图片 20 MB、视频
  50 MB、音频 15 MB，累计有效上传预约最多 5 GB。上传完成后必须登记用户归属，
  未登记的任意远程 URL 不得作为生成输入；每日任务清理已过回调宽限期的孤儿
  Blob 和过期预约。
- 服务端抓取 Provider 输出和代理下载时必须只连接公共 HTTPS 地址，逐跳校验
  DNS 与重定向，并执行内容类型、文件签名、总时限和实际流量上限；图片、视频、
  音频输出上限分别为 40 MB、500 MB、50 MB。

### 8.1 数据库访问边界

- 浏览器不得通过 Supabase Data API、PostgREST 或 GraphQL 直接访问核心业务表；
  所有业务数据访问必须经过 Next.js Server 和 Prisma。
- `User`、`Subscription`、`CreditBatch`、`Generation`、`MediaAsset`、
  `GenerationMedia`、`ProcessedStripeEvent`、`MediaUploadGrant` 和
  `_prisma_migrations` 不向 `anon`、`authenticated` 或 `service_role`
  数据库角色开放直接访问。
- 这些表在 `public` Schema 中必须启用 RLS 作为纵深防御，但在当前 NextAuth
  架构下不为浏览器角色创建用户级 Policy。
- 数据库权限收紧后，Next.js Server 的 Prisma 读写、Stripe Webhook、Cron、
  生成、历史和媒体生命周期行为必须保持不变。
- Prisma Runtime 使用专用 `NOBYPASSRLS` 角色和显式 Server Policy；Migration
  使用独立 Owner/Admin 直连，并且 Runtime 不得访问 `_prisma_migrations`。
- Supabase Data API 必须关闭；Supabase 仅承担 PostgreSQL、Auth、Storage 等
  基础能力。

## 10. 积分、套餐与结账

生成消耗积分。参数校验、登录和用户积分不足应在扣费前完成。扣费后发生的
Provider、超时和媒体持久化失败必须退款。

| 套餐 | 月付价格 | 年付价格 | 每月积分 | 输出权益 |
| --- | ---: | ---: | ---: | --- |
| Starter | $16 | $96 | 200 | 最高 720P |
| Pro | $48 | $288 | 800 | 最高 1080P |
| Max | $96 | $576 | 2,400 | 最高 1080P |

- Pricing 弹窗同时展示 Starter、Pro 和 Max 三个套餐，并提供 Monthly/Yearly
  切换；每次打开默认选择 Yearly，并明确展示 `Save 50%`。

## 11. 失败处理与退款

用户不得看到 Provider 余额、API Key、内部字段名、原始 Provider 响应或基础
设施凭据。所有生成失败必须说明发生了什么、用户下一步做什么、是否适合重试，
以及积分是否已退回。

| 错误码 | 用户含义 | 是否可直接重试 | 积分处理 |
| --- | --- | --- | --- |
| `auth_required` | 登录状态已过期 | 重新登录后可以 | 未扣费 |
| `prompt_required` | 缺少 Prompt | 修改后可以 | 未扣费 |
| `input_image_required` | 当前模型需要图片 | 添加输入后可以 | 未扣费 |
| `unsupported_file_type` | 文件格式不支持 | 更换文件后可以 | 未扣费或退款 |
| `file_too_large` | 文件超过模型限制 | 更换文件后可以 | 未扣费或退款 |
| `invalid_image` | 图片损坏或不可用 | 更换图片后可以 | 未扣费或退款 |
| `invalid_parameters` | 参数不受支持 | 修改后可以 | 未扣费或退款 |
| `content_policy` | 请求被安全策略拦截 | 修改后可以 | 退款 |
| `insufficient_credits` | Flownana 用户积分不足 | 不可以 | 未扣费 |
| `credit_conflict` | 并发操作改变了余额 | 刷新后可以 | 不重复扣费 |
| `provider_unavailable` | 模型暂时不可用 | 稍后重试或换模型 | 退款 |
| `rate_limited` | 请求过多 | 稍后可以 | 退款或任务继续 |
| `timeout` | 超过允许处理时间 | 检查历史后可以 | 退款 |
| `network_error` | 网络连接中断 | 可以 | 未扣费或退款 |
| `media_processing_failed` | 结果无法安全保存 | 可以 | 退款 |
| `task_not_found` | 任务不存在 | 不可以 | 不额外扣费 |
| `generation_failed` | 未识别生成错误 | 可以 | 退款 |

补充规则：

- 原始 Provider 信息只记录在服务端日志。
- 可修正的内容、输入和参数失败使用警告样式；服务和基础设施失败使用错误样式。
- 操作按钮根据场景显示 Edit request、View plans 或 Try again。
- 自动退款失败时必须明确提示联系支持，并保留继续重试退款所需的状态。
- `generation_failed` 埋点记录稳定错误码，不记录 Provider 原文。

### 17.1 Home 布局与普通创作

- `/` 保留当前共用导航、账户菜单和公司页脚规则；页脚仅未登录显示，背景与
  生成区一致。移除 Featured capabilities、文字示例及整个 Recent creations。
- “What will you create today?” 和输入区上移，成为首屏视觉重心；下方展示图片
  Templates 模块。首版不在 `/image` 增加 Templates 或热门标签，不增加搜索筛选。
- 普通输入完整复用 Image/Video 的附件、模型、参数、积分展示及校验能力。
  用户在 Home 发起生成，任务提交成功后立即进入对应 `/image` 或 `/video`，
  在工作台展示进度与结果，不等待全部生成完成才跳转。
- 输入、附件、参数及已提交任务完整承接，不重复提交或扣费；校验、积分不足或
  提交失败时保留输入并提示。普通创作保留现有模型及输出数量规则。

### 17.2 模板范围与模型

- 首发全部 16 个模板：Poster、Interior design、Logo、Illustration、Headshot、
  Icon、Product photo、Merch、Infographic、Flyer、Book cover、App mockup、
  Packaging、Advertisement、Thumbnail、Website mockup。
- Home 使用紧凑图片卡片：桌面一行 6 个，名称叠在图片左下角，不展示模块副标题或卡片用途文案。界面沿用英文，支持中英文输入。
- 需求理解与多模态问答固定使用 OpenRouter 的 Qwen3-VL-32B-Instruct；不做
  LLM 路由、无声 fallback 或无限问答。准确 API ID 和能力在接入时核验。
- 模板生图统一使用现有 KIE GPT-Image-2.5 Sunburst，包括初次生成和继续编辑；
  不提供任意图片模型选择，不自动切到 Flare。确认区明确展示固定模型。
- 普通创作不受模板模型限制。选择图片模板进入图片模式，但不销毁原 Image/Video
  草稿；退出模板恢复普通草稿与模型。
- 保留附件 PRD 的 instruction、结构化规则、问题流程、输出策略和版本概念；
  来源原文作为提供的参考材料保留，不宣称已验证 ChatGPT 内部协议或官方模板 API。

### 17.3 模板问答与确认

- 点击模板在 Home 打开面板，先接受文字和图片，再提取已有信息；已回答的问题
  不重复询问。模板定义候选问题及静态选项，不让 LLM 任意发明 UI 或字段。
- 支持文本、长文本、单选、自定义单选、多选、视觉单选和必选/可选图片上传。
  通常最多 3 个问题，个别模板最多 4 个，由模板配置固定；支持返回修改。
- 必要事实不可跳过或猜测。风格等可选信息允许“由系统决定”；达到问题数上限
  仍缺必要事实时提示补齐，不强行生成。Logo 可选参考上传不单独增加问答步数。
- 信息完整后进入确认态，不自动生图：展示需求摘要、参考图、方向、固定模型、
  比例、分辨率、张数及总积分，用户点击 Generate 才提交。
- 修改 brief 或参考图后重新核对规格和报价，不能提交过期规格。
- 游客可浏览模板和填写文字；上传图片或调用 Qwen 前登录，保留已填内容。
  已登录模板问答支持关闭后恢复；不同模板答案不得混用，恢复数据按账号隔离。
- 初次调用及每轮回答可同时返回下一题或最终规格，避免独立重复的最终整理调用。
  三题流程最多 4 次正常 LLM 调用，四题流程最多 5 次；解析失败允许额外重试一次，
  再失败保留输入并提示重试，不扣图片积分。

### 17.4 输出与继续编辑

- 初次模板生成默认 4 个独立候选方案，允许用户覆盖为 1–4 张。每张具有明确方向，
  共享同一 brief 和事实；用户指定的类型、构图或差异维度优先于默认多样性。
- 一个点击对应一组任务，不要求 Provider 单次调用，不把四宫格合成为一张图片。
  成功提交后进入 `/image`；成功结果逐张出现，桌面默认 2×2，手机单列。
- 选定某张继续编辑时，默认 1 张，锁定所选方向，允许主动增加张数。复用工作台
  输入和参考能力，携带选定结果、必要原始参考、必显文字及最新修改要求。
  不自动重新展开四个方向，不新增独立编辑器。
- 历史保留模板、版本、答案、方向及编辑关联，支持继续修改；保留现有下载等操作。
- 模板封面不自动作为生图参考。静态视觉选项仅表达方向；配置明确需要风格图时
  才传入。附件区分主体、风格、布局、品牌素材和待编辑结果，歧义时才询问。
- Logo 品牌身份与画面必显文字分开；独立符号允许无文字。若同时要求完整品牌
  文字和无字符号，需明确解决冲突。不能把参考图文字自动视为必显文案。
- Headshot 必须上传人物照片；空间、商品图及缩略图推荐参考图；其余按模板规则。
  用户事实、日期、价格、品牌名不能被 LLM 翻译或扩写覆盖。
- Icon 每个候选可是一套图标的视觉方案图；Mockup、Packaging 等交付概念图片。
  首版不承诺 SVG、独立图标拆分、可运行网页、设计源文件或印刷刀模。
- 暂不增加透明 PNG 保证、局部圈选/Mask、Sketch 或独立质量档。比例、分辨率和
  上传限制沿用现有 Sunburst 能力；截图“高”不映射为 2K。

### 17.5 积分、任务与数据

- 问答不额外收用户积分；图片按现有 Sunburst 每输出规则计费并展示总额。
  沿用失败退款和五输出活跃上限；名额不足提示等待，不静默减张或增加后台排队。
- 部分失败时保留成功结果，只退失败输出积分。重试失败方向需用户主动点击，
  展示费用后创建新任务，不自动再次发起付费生图。
- 任务组及方向使用稳定标识，重复点击、网络中断、跳转和恢复不得造成重复扣费
  或重复创建。账号隔离、媒体持久化、删除和引用规则沿用现有实现。
- 保存模板版本与运行状态，问答/任务恢复兼容现有账号和 Generation 体系。
  数据结构可按工程适配；生产数据库迁移和部署仍须另行批准。

### 17.7 本地开发版事件口径（2026-09-11）

- `template_view`：卡片至少 50% 进入视口，同次 Gallery 挂载每模板一次；
  `template_click`：点击卡片打开面板。
- `template_input_submit`：已登录需求/回答请求返回有效运行状态时记录，每次显式提交一次；
  失败运行状态也可记录提交，不代表问答成功。
- `clarification_started`：未提交过答案的输入首次返回问题；
  `clarification_completed`：显式提交后进入 ready，携带已填写答案数。
  返回修改后重新确认可再次记录；关闭恢复不补记这些事件。
- `variant_selected`：点击模板结果的编辑或失败重试入口；`continued_edit` 仅成功结果编辑。
- `generation_started`：任务组首次接受一次，重放不记录；结果事件逐输出记录，
  仅记录工作台观察到的活跃任务完成，按账号/输出 ID 在 sessionStorage 去重。
  历史已完成结果不补记，关闭浏览器期间完成的任务可能漏记，不作为扣费账本。
- 下载沿用 `result_download_clicked` 并附带模板 ID。所有模板事件不上传原始输入、答案或图片 URL。

### 18.1 入口与会话

  分辨率、张数等后置参数选择器，支持文字与参考素材，通过自然语言表达要求。上传按钮统一使用与 Image/Video 一致的“+”。

- 点击任一现有图片模板直接进入 Agent 会话，携带模板背景与输入引导；取消模板

- 侧栏不设置独立 Agent 标签入口；保留会话记录，支持新建、自动标题、重命名、删除及重新打开
  继续交流。会话上下文独立，按账号隔离，刷新或重新打开可恢复已保存内容。
- 删除会话保留 Assets 中的生成作品；不等于删除作品。活跃任务及仅输入素材的

### 18.2 对话与内容生成

- Agent 支持创意讨论、文案整理、图片生成与继续编辑，以及视频生成。
  视频能力限定于现有在售模型支持的输入与输出能力，不新增音乐或高级视频编辑器。
- 会话内理解需求，必要时追问；问题可附可点击选项，也可直接打字回答。
  保留已有需求、回答与参考素材；修改要求后重新核对受影响的方案和报价。
- 方案、付费确认、生成状态与结果均在当前会话内展示，不因生成跳转 Image/Video。
  图片结果逐张出现，允许选定一张继续修改，保留必要参考、文字事实及编辑方向。
- 同一会话可先生成图片，再选择其中一张生成视频；各次付费操作分别确认，
  不将同意生图解释为同时授权视频生成或其他后续付费步骤。
- 生成作品进入 Assets，复用现有下载、持久化、所有权、引用与删除规则。
- 模板仍为现有 16 个图片模板。模板初次默认 4 张、允许 1–4 张；编辑默认 1 张并
  锁定所选方向。普通 Agent 按需求决定数量并在确认卡片中展示，不统一默认 4 张。
- Agent 自动确定适用模型及参数；用户通过对话提出规格要求，确认卡片展示实际
  模型和规格。默认图片模型为 GPT-Image-2.5 Flare；理解使用现有 Qwen，先验收

### 18.3 付费与执行边界

- 每次付费生成前展示方案、参考素材、实际模型、输出数量、适用规格及总积分；

- 需求、参考或规格变化后必须重新核价；过期确认不得执行。重复点击、刷新和
  网络恢复不得重复创建任务或扣费，模型输出本身不能代替用户付费确认。
- 图片/视频沿用现有逐输出计费、失败退款和五输出活跃上限；部分失败保留成功
  结果，只退失败输出。重试由用户主动发起并再次确认费用，不自动付费重试。
- Agent 对话不扣媒体积分：免费每天 10 次、付费每天 100 次。得到一次完整回复
  计一次，追问也算；回复失败、生成确认、进度查看和历史恢复不算。额度按账号
  共享，不是会话数或媒体生成次数。每日 UTC 00:00 重置，显示用户当地重置时间。
  用完保留输入，不自动扣积分续聊；媒体仍另行确认积分。

## 20. 待确认：性能优化中的展示读取与恢复拆分（2026-09-14）

### 范围与边界

- 历史、Agent 会话/列表及账单摘要的纯展示读取，使用与注册时间绑定的一致性
  只读快照，不再取得 User 排他锁。所有扣费、退款、生成预约、写入、删除及报价
  确认保留既有事务锁和服务端重新校验，展示快照不能授权任何付费操作。
- 展示接口允许先返回已持久化状态。由该读取触发的过期任务、退款和 Blob 清理
  恢复改为响应后执行；处理结果由既有后续刷新收敛。恢复失败保留数据库义务，
  后续请求继续重试；不能通过删除恢复逻辑或丢弃失败记录提高响应速度。
- Agent 过期回合落库也移出展示读取。暂停/失败状态在后台落库后由轮询更新；
  新消息、报价确认和删除仍同步检查真实状态，不接受过期报价或突破活跃上限。
- 同账号多条展示请求可以合并后台恢复。合并仅作性能优化，不将进程内状态当作
  退款、租约或清理是否完成的事实来源；不同账号及重新注册后的账号不能合并。
- 不增加套餐、积分、模型、数据库结构或 GA4 事件，不修改收费/退款金额或媒体
  留存规则，不允许跨账号私有缓存。生产发布继续另行授权。

### 开发前确认与验收

确认范围为上述只读快照、响应后恢复及合并执行的本地开发和隔离测试。
生产迁移/部署和真实付费测试不包含在内。必须通过：

1. 一个请求持有 User 写锁时，同账号历史、Agent 和账单展示读取能够完成，且
   返回同一已提交快照，不出现半次扣费或部分生成预约状态。
2. 旧 JWT、删除后重建账号、跨账号会话 ID 和读取中发生账号变化，不得返回
   新账号的数据或重新绑定旧会话；前端继续校验服务端 accountScope。
3. 单次/并发恢复、进程中断后重试、退款失败、Blob 删除失败/超时和过期租约，
