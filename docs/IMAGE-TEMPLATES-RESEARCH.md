# ChatGPT Images 2.5 模板与 Flownana 需求核对

## 结论

模板生图限定 GPT-Image-2.5 系列，符合当前已确认方向。ChatGPT 的模板体验包含需求收集和编辑流程；仅切换图片模型不会自动获得这些产品能力。Flownana 仍需实现模板配置、Qwen 问答、需求确认、差异化任务和结果编辑上下文。

建议首版模板固定 GPT-Image-2.5 Sunburst；这是一项质量优先的产品建议，具体版本已获后续确认。普通 Image/Video 创作仍保留现有模型选择。选择模板后需明确显示使用的模型，退出模板恢复普通草稿和模型，不静默覆盖。[2][3][4]

## 证据与适用范围

核对日期为 2026-09-10。公开证据包括 OpenAI 9 月 8 日发布说明、帮助中心、两款模型文档、图片 API 与提示指南。另对照提供的完整 PRD、ChatGPT 图片页截图及当前 Flownana 源码。

官方帮助确认模板支持从类别或模板进入、补充需求、选择或自由填写追问答案，以及在可用时上传参考图。生成后可以继续描述修改。[1]

截图显示的是任务类别入口：Poster、Interior design、Logo、Illustration 等，卡片以图片为主；不能由封面推断产物必须保持同一风格。完整 16 项清单和 instruction 原文来自提供的 PRD，未独立核验其官方导出来源。

后台访问 ChatGPT 图片页返回未登录界面。此次未完成登录态模板点击到问答再到生图的完整实测，也没有调用付费模型。官方公开资料没有确认固定三题、所有模板四张、Qwen、内部 JSON schema 或模板专用 API。以上不能作为 ChatGPT 内部实现事实。

## 产品层与模型层

| 层次 | 负责的工作 | Flownana 方案 |
| --- | --- | --- |
| 模板入口 | 帮助选择任务类型 | Home 输入区下方的 16 张模板卡 |
| 需求整理 | 从文本/图片提取已知信息、问缺失项 | OpenRouter Qwen，预设问题与严格校验 |
| 生图 | 从文字和参考图生成候选图片 | GPT-Image-2.5，通过现有 KIE 接入 |
| 编辑 | 承接选定图片与修改要求 | `/image` 复用创作工作台，保存模板约束 |

公开图片 API 支持生成与编辑；Responses API 另提供对话上下文机制。现有 KIE 请求不会因为采用同系列模型就自动拥有 ChatGPT 的会话状态。Flownana 应显式携带编辑依据。[5]

## 模型选择

OpenAI 将 Flare 定位为快速日常生成，将 Sunburst 定位为更注重精确编辑的模型。两者都接受文字和图片；官方未公开说明截图中每个模板的内部模型选择。[2][3][4]

建议 16 个模板先统一 Sunburst，减少模板之间质量差异和模型选择负担。不要按模板自动路由到不同模型，也不要把无声回退引入首版。实际速度、成功率和质量必须用 KIE 链路测试，不能把官方 API 的延迟宣传直接当作平台承诺。

代码 `lib/generation-pricing.ts` 已定义 Flare/Sunburst 的文生图和图生图 Provider ID；两者当前平台配置均为 1K/2K/4K 每张 2/3/5 积分，因此四张为 8/12/20 平台积分。这是当前本地计价配置，不是本轮重新核实的上游实时价格。

## 建议补充的交互规则

### 模板是任务入口

卡片封面展示用途示例，不默认作为生图参考。静态风格选项图主要用于选择；只有配置明确标记为需要传入的风格参考时才交给生图模型。避免把示意图中的人脸、文字、商品误带进结果。

已有普通创作草稿与模板草稿分开保存。选择图片模板时进入图片模式，但不销毁未提交的视频草稿。关闭模板面板返回 Home，已登录模板问答可恢复。

### 问答后保留最终确认

信息完整时可直接进入确认态，不为凑进度强制提问；信息缺失才展示问题。确认态显示所选模板、需求摘要、参考图、方向、张数、分辨率、比例和总积分。默认四张是 Flownana 的已选策略，不宣称是 ChatGPT 所有模板的固定行为。

生成之前修改 brief 或参考图后，旧规格和报价必须失效并重新核对，不能拿旧答案生成新任务。最多问题数仅限制 AI 追问，必要事实没补齐不能自动猜测。

### 继续编辑默认一张（新增建议）

首次探索默认四方向；选中某个结果继续修改时，建议默认一张并锁定所选方向，不再次自动扩展四方向。用户仍可主动改为多张。编辑保留选定结果、必要原始参考、必显文字及最新修改要求；每次请求只明确当前要改什么、哪些要保留。

例如“仅将背景换成米色”不能重新运行一个四方向 Logo 探索流程。这项默认数量变化已获后续确认。

## 参考图与文字规则

建议内部标记每张附件的角色：人物/产品/空间主体、布局、风格、品牌素材、待编辑结果。只有存在多种可能时才让用户确认角色，避免增加通用问答步骤。

Logo 的品牌身份与画面必显文字分开；独立符号允许没有文字，但不能同时接受“必须出现完整品牌名”而不处理冲突。视觉参考里的文字不自动成为必显文案。

Renderer 应使用清晰可维护的描述，不机械填满空字段。原始品牌名、数据、日期保持逐字值；Qwen 的提取或翻译不能覆盖这些值。官方提示指南要求明确保留项，并指出重复编辑仍可能改变细节，因此需要检查结果，不能承诺像素级不变。[6]

## 参数、透明背景与交付物

当前 KIE 适配代码仅为该系列提交 prompt、aspect_ratio、resolution、input_urls，没有透明背景、mask 或独立 quality 参数。ChatGPT 截图中的“高”不能直接等同于 Flownana 的“2K”。

官方 API 的背景、质量、尺寸是独立参数；透明输出需要相应配置和支持 alpha 的文件格式。[5] 在 KIE 参数及真实输出未核验前，首版不新增“透明 PNG”保证、局部圈选编辑或官方质量档映射。Logo/Icon 可先交付背景明确的栅格方案。

Icon 模板每个候选代表一套图标视觉方案，可以是一张包含多图标的图片；不是承诺四张分别是四枚不同图标，也不承诺自动拆分 SVG。App/Website mockup、Packaging 交付概念图片，不增加代码、设计源文件或刀模输出。

## 状态、计费和验收

一个四方向请求需按整组意图处理重试与网络中断，方向有稳定 ID，避免重复提交及扣费。已被接受的任务在 `/image` 继续运行；成功输出逐张出现，失败不阻塞其他输出，按现有规则退款。用户明确点击失败方向重试后才创建新付费任务。

沿用最多五个活跃输出限制。四张任务名额不足时提示等待，不静默降为两张、不引入未批准的排队系统。后台不能仅凭前端检查假设名额仍然有效。

模板技术成功率建议同时报告“单张成功率”和“整组全部成功率”。文字正确、人物和产品保真、四方向有效差异属于质量指标，不能由 HTTP 成功或 JSON 可解析代替。

160 个案例分为：问答/字段合同、任务/退款/重试合同、真实模型视觉验收。真实验收重点为 Logo 文字冲突、商品包装标签、人像身份、海报日期、小字信息图、三轮定向编辑。付费测试预算单独确定。

## 已接受范围与待确认变化

已接受：Home 模板入口、问答后确认生成、现有积分和退款规则、人工重试失败方向、模板埋点衔接、沿用英文界面和中英文输入。模板生图现已明确限制 GPT-Image-2.5，替代此前任意现有图片模型建议。

后续已确认：模板统一 Sunburst；继续编辑默认一张。素材制作责任此前没有明确单一选项，仍需确定是提供成品还是由 Flownana 制作；不能把“按建议来”解释成素材已经齐备。

实现前应将已接受条款整合进 PRODUCT，并区分这些新增建议。研究结论不代表功能已实现或已发布。
