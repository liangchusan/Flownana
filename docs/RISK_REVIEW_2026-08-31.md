# 2026-08-31 本地风险检查交付

结论：本轮仓库检查发现的六项安全问题已完成本地修复，相关可靠性与客户端问题
也已收尾。所有改动仍在工作区；没有提交、推送、生产迁移或部署。

## 主要修复

| 风险 | 实现边界与结果 |
| --- | --- |
| 删号后旧 JWT/旧请求跨注册使用 | Session 与服务端操作绑定 User.createdAt，不允许普通请求重建账号 |
| 年付月末多发第十三批积分 | 统一原始 UTC 月份锚点，最多十一批后续积分，兼容旧指针 |
| 乱序 Stripe 事件恢复取消状态 | User 锁内重新读取 Stripe；终态不可逆，周期不可倒退 |
| 旧已支付 Checkout 为当前未支付周期发积分 | 校验 Invoice、Customer、订阅项、Price 与精确起止周期 |
| 多次结账重复消费旧订阅价值 | 持久化 CheckoutReservation、UpgradeConsumption、不可变幂等请求及共享发放事务 |
| 绕过前端五输出限制 | User 锁内一起预约、扣费、保存 pending 和输入引用，图片/视频混合计数 |

其他修复包括退款/Blob 清理义务保留、重复媒体保存及删号竞态、跨账号缓存和请求
隔离、迟到响应与历史合并、重复/多类型输入恢复、未知结算状态不误报失败，以及
模态窗口键盘/焦点边界。未改变套餐、价格、积分、退款政策、在售模型或 GA 事件。

主要新增共享模块：`lib/checkout-reservation.ts`、`lib/upgrade-consumption.ts`、
`lib/billing-transaction.ts`、`lib/generation-lifecycle.ts`、
`lib/generation-response.ts`、账号 scope/operation 模块和 `components/ui/modal.tsx`。
各调用路由、客户端及测试一并更新；实现与运行边界见根 `MEMORY.md`。

## 剩余风险与发布前置条件

1. 外部 Stripe、Google、Provider 和 Blob 的真实集成未在本轮验证；本地替身
   不证明线上平台行为。生产没有应用这些修复。
2. 生产迁移与部署需单独批准。应先迁移，再确保旧结账请求结束后切换新代码，
   不能让不使用预约的旧代码与新代码同时创建支付入口。
3. 大量历史数据（超过每轮 1000 个 Session/100 个本地历史订阅）、已重复支付、
   到期但无法确认的预约会失败关闭并需要运营对账，不能直接清记录后重试付款。
4. Stripe 取消、Blob 删除与数据库提交不能组成同一外部事务。历史上未登记的
   孤儿媒体、丢失的扣费快照以及 Provider 接受请求但未回包的成本需单独对账。
5. GA `purchase_success` 的 URL 驱动上报、营销素材及部分模型/分辨率文案仍按
   原范围保留；相关产品/埋点决策不在这次结账批准中，不擅自重定义。

本报告是本地修复交付，不是零风险保证或生产发布完成证明。
