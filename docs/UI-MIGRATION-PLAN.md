# Flownana UI 更换方案：Runway 基调 × Flownana 品牌

日期：2026-09-12。
状态：用户已确认 Runway 为基调、品牌蓝黄为点缀；本文件细化设计与技术方案。
本轮授权为方案编制，不代表已开发或已授权生产部署。此前 Mobbin 方案由本文件替代。

## 1. 目标与来源

打造清晰、克制、以作品为中心的媒体创作工作台：白色阅读画布、黑色主操作、
中性灰层级、深色媒体预览，加上固定角色的 Flownana 蓝黄品牌点缀。

参考：[getdesign Runway 分析](https://getdesign.md/runwayml/design-md) 与
[设计预览](https://getdesign.md/design-md/runwayml/preview)。2026-09-12 已核对两页。
它们是第三方独立分析，不是 Runway 官方组件库。页面简介强调深色电影感，
实际预览包含白色阅读区与黑色胶囊按钮；本方案采用适合工作台的浅色主体。
本轮未执行 `npx getdesign@latest add runwayml`，未获取 CLI 完整文件。

参考内容只作为视觉依据。下文数值是 Flownana 的拟定实施值，不宣称是 Runway
官方 Token，也不把品牌 Logo 原图色等同于可读性调整后的 UI 色。

## 2. 范围与固定边界

全站活跃页面统一适配：Home、Agent、Image/Video、Assets、Pricing 页面与弹窗、
Profile/Billing、登录提示、Contact/法律页，以及加载、错误、空态和弹窗。
不恢复已下线营销首页，不新增暗色主题开关、搜索、收藏、批量操作或其他产品能力。

保留已批准的路由、页面内容、导航项、模型、价格、订阅、额度、退款及素材生命周期。
保留全部既有 GA4 触发条件、含义、去重与隐私规则；不迁移数据库、不替换业务 API。

特别保护：

- Home 的 Agent/Image/Video 三模式、16 模板入口、登录前后草稿承接。
- Image/Video/Assets 之间保持挂载的工作台、共享附件和活跃请求。
- Agent 会话恢复、最近会话折叠/新建/改名/删除、付费前明确确认与失效报价。
- 模板封面 4:5 与既有响应式列数；生成媒体保持原比例，不套用图库封面裁切规则。
- 共用侧栏 260px 展开/64px 收起、横版 Logo 96px、现有移动抽屉和 Details 行为。
- 原生 dialog 的背景隔离、焦点循环、嵌套 Escape、滚动锁和关闭后焦点恢复。

## 3. 品牌规则

### 3.1 识别方式

稳定复用三个识别点：蓝黄 Logo、海面生成等待动画、蓝色交互反馈。
白色工作台突出原创模板封面及用户作品，避免与其争夺色彩注意力。
不再添加第二套装饰符号，不将蓝黄做成大面积渐变或每张卡片的边框。

Logo 使用 public/brand 下现有 PNG 和 components/ui/logo.tsx，保持原比例和色彩；
深色场景只将字标转白，彩色图标保持原样。侧栏使用当前尺寸，手机顶栏不新增 Logo。
现有图标留白区域不额外放纹理或图案。若图片复杂则使用独立中性底承载标识。

### 3.2 颜色的职责

- 黑色：Generate、发送、确认生成、订阅等当前区域最主要操作。
- 蓝色：链接、键盘焦点、已选参考素材和当前可操作对象的选中反馈。
- 黄色：Logo、已有加载动画中的品牌图形；必要的静态品牌引导可用极浅黄底。
  第一版不新增欢迎横幅或黄色促销标签，不强行为每页分配黄色元素。
- 中性灰：导航选中、次要按钮、分隔、层级与辅助信息。
- 状态色：危险、成功、警告保持独立语义；配文字/图标，不仅依赖色差。

现有能选中素材的交互可使用蓝色反馈，但不因此给 Assets 新增选择或批量模式。
黄色不能代表“推荐套餐”“生成成功”“账户警告”等多种冲突含义。

## 4. 拟定颜色 Token

| 角色 | 拟定值 | 用法 |
| --- | --- | --- |
| background / card / popover | #FFFFFF | 页面、卡片、浮层主体 |
| foreground | #111111 | 标题和主要文字 |
| text-secondary | #404040 | 正文、次级信息 |
| muted-foreground | #666666 | 说明、时间、元数据 |
| surface-soft | #F7F7F7 | 侧栏、安静分区、hover |
| surface-strong | #EEEEEE | 中性选中与次级控件 |
| border | #E5E5E5 | 装饰分隔与卡片边界 |
| input | #8A8A8A | 需要独立识别的输入边界 |
| primary / primary-foreground | #111111 / #FFFFFF | 主按钮 |
| primary-active | #2B2B2B | 主按钮 hover/active |
| brand-blue / ring / link | #0066CC | 浅底上的链接、焦点、素材选中 |
| brand-blue-soft | #EDF5FF | 蓝色选中区域的浅底，配蓝边/图标 |
| brand-blue-on-dark | #75B8FF | 深色区域必要的蓝色交互反馈 |
| brand-yellow | #F5C542 | 品牌点缀候选，不替换 Logo 原图颜色 |
| brand-yellow-soft | #FFF8DB | 少量品牌引导底色，配深色字 |
| surface-dark | #1A1A1A | 媒体预览场景 |
| surface-elevated | #292929 | 深色媒体控件表面 |
| destructive | #B42318 | 错误和破坏性操作 |
| success | #18794E | 成功状态 |
| warning | #8A5A00 | 警告文字，配图标与说明 |

品牌 UI 蓝黄为候选值，开发样板阶段应与 Logo 原图并排检查协调性；
无需把 Logo 颜色逐像素复制到小字号链接。视觉比例以中性界面占绝大多数为原则，
不要求对图片、Logo 或加载动画计算机械百分比。

实际检查组合颜色及透明度后的对比度：普通文字至少 4.5:1，大文字和关键图形
至少 3:1。浅边框只作分隔，不能承担唯一的输入/选中/焦点辨识职责。
黄色上只用深色文字；蓝色不可见时仍有勾选、边框或文字状态。

实现保留现有 RGB 通道变量与 Tailwind 3 映射。primary 不再兼任品牌色；
新增 brand、link、text-secondary 等语义角色，分别审查旧 primary 调用位置。
清理 warm Stone 硬编码时按语义处理，不把全部 Stone 机械替换成某个 Gray。
保留禁止 JSX 任意 Hex、内联 style 与直接 Slate/Gray 色系漂移的工程规则。

## 5. 字体、形状、间距与动效

### 字体

统一 Inter，中文使用系统无衬线回退。保留 Logo 自身字形，不引入参考中的专有字体。
移除页面 Cormorant 展示字体，并在确认没有引用后移除其下载。

| 场景 | 桌面 | 手机 |
| --- | --- | --- |
| Home 主标题 | 40px / 48px，500 | 30px / 38px，500 |
| 普通页面标题 | 28px / 36px，500 | 24px / 32px，500 |
| 面板/弹窗标题 | 18–20px，600 | 18px，600 |
| Agent 正文、输入 | 16px / 26px，400 | 16px / 26px，400 |
| 导航/按钮/标签 | 14px / 20px，500–600 | 同桌面 |
| 元信息 | 12–13px / 18px | 同桌面 |

价格、总积分和付费确认正文不得降为弱化小字。长中文不使用挤压字距；
标题允许换行，不截断关键信息。工作台不因换肤新增标题栏。

### 形状与密度

- 主/次按钮、模式选择器：胶囊；图标按钮保持圆形或既有轻量方形。
- 普通输入、菜单：8px；报价卡、模板、结果外框：12px；Composer、Modal：16px。
- 无衬线标题、细分隔和有限卡片嵌套建立秩序，媒体优先。
- 4px 基础间距；控件内部 8–12px，面板内部 16–24px，页面区块 24–40px。
- 手机横向内边距 16px，桌面 24–32px；沿用现有内容宽度与列数，不扩大工作区。
- 核心触控区域至少 44px；紧凑图标外扩点击区域，不强行放大图形。
- 卡片默认无阴影；浮层仅保留弱阴影作为必要分层，不能全站删除浮层分离反馈。

### 动效

保留 transition-all duration-300、轻量 active 反馈与现有品牌海面动画。
不新增全屏背景动效；减少动态偏好下停止非必要漂移，仍显示真实处理状态。
加载骨架与最终布局一致，选中边框不能改变盒尺寸而引起跳动。

## 6. 基础组件规范

| 组件 | 外观与状态 |
| --- | --- |
| Button | 黑底白字主操作；浅灰次操作；文字/图标 ghost；删除用危险色；禁用同时具备语义属性与清晰状态 |
| Input/Textarea/Composer | 白底、有辨识度边界；聚焦蓝环；错误边界与说明；多行内容可读，上传/发送位置保持 |
| Tabs/模式 | 中性底分组，选中以对比表面和字重表达；保留当前切换逻辑 |
| Sidebar row | 默认安静，hover 浅灰、选中较强灰；蓝色只留给焦点，不把整栏涂蓝 |
| Card/报价 | 白底细边界，模型/规格/数量/总积分有清晰层级；确认按钮黑色；失效报价禁用并解释 |
| Menu/Modal | 白底、分隔、适度圆角和弱浮层阴影；完整键盘交互及焦点回归 |
| Media controls | 深色或半透明中性底、可读图标；触控常显、桌面 hover/focus 显示规则保持 |
| Toast/状态 | 文本与图标明确表达处理中、失败、退款待处理；不虚构执行过程 |

保留现有组件 props/ref 和事件，优先修改 components/ui 的视觉实现；
不替换 Modal 为新的弹窗库，不用新依赖重建基础交互。

## 7. 页面落地

### Home

白底、浅灰侧栏、Inter 标题、白色 Composer 和黑色发送/生成按钮。
三模式与参数维持原位置和行为，Agent 不显示后置参数。模板保持 4:5，
桌面六列、平板四列、小屏三列、手机两列与 12px 间距，封面及标题遮罩保持。
未登录页脚随页面保持白底；登录中和登录后不闪现页脚。

### Agent

对话主体白底，用户消息采用浅灰中性表面；回复以正文和媒体为主。
回答选项用中性轮廓按钮，已有选中状态可加蓝色标识。报价卡用细边界，
总积分、规格与确认操作清楚突出。选定图片用蓝框和标识，保持单图编辑语义。
额度用完、报价过期、部分失败、退款待处理、历史恢复均有明确状态样板。
侧栏最近会话的展开/新建/更多菜单及自动标题不变。

### Image / Video

统一 Composer、参数菜单、历史和 Details 的黑白灰层级。
已选附件以蓝色提示，不兼容附件保留错误说明与移除入口。
生成结果无裁切；海面等待动画保留；参数、预计积分与失败信息不因简化视觉而隐藏。

### Assets 与预览

作品承担主要视觉色彩，卡片、筛选和现有操作保持中性。
沿用现有资产布局，不新增瀑布流或选择模式。完整媒体预览使用深色底，
视频播放、声音、下载与关闭保持清晰，深色组件使用独立的前景/焦点颜色。

### Pricing / Account / 公共页面

白底、黑色 CTA；推荐套餐用轻量灰底或轮廓，保留既有推荐标识和文案，
不新加黄底促销。套餐数量、年/月付默认、积分和限制保持现状。
账户表单保留完整输入边界和验证提示；永久删除账号的危险语义保持。
法律正文和联系信息不改写，保留既有头尾部显隐规则；已有深色页脚采用中性深色。

## 8. 技术迁移与文档顺序

现有 Next.js 16 / React 19 / Tailwind 3 与组件结构足以实现，不升级框架。

1. **基线**：隔离分支建议 codex/ui-runway-migration；记录当时工作树和提交，
   留存 390/768/1440px 关键页面和状态截图，列出活跃路由与共享浮层。
2. **参考归档**：实施前在临时目录检查 getdesign CLI 版本/帮助/生成结果，
   记录版本与来源，将参考资料放 docs/references；不覆盖项目 DESIGN.md。
3. **规范生效**：PRODUCT 记录已确认方向与完整边界，细则审批后更新 DESIGN
   的现行章节和 AGENTS 旧视觉措辞；删除旧规则冲突，而非留下两套有效规范。
4. **设计系统**：修改 globals.css、tailwind.config.ts、components/ui；
   在 /design-system 展示色板、字体、完整状态及深色媒体控件。
5. **代表页样板**：Home + Agent，包括手机、报价及生成状态，校正候选色和密度。
6. **全站适配**：共用外壳 → Image/Video/Assets → Pricing/Account/公共页。
   逐项清理旧字体、Stone/珊瑚色、圆角覆盖和硬编码阴影。
7. **回归收尾**：完成检查矩阵，记录实际截图、失败修复、未验证外部链路，更新 MEMORY。

app/globals.css 管颜色变量；tailwind.config.ts 管语义映射与字体/圆角；
components/ui 管基础样式；components/blocks、creation、generate 管业务组合。
app 页面只进行必要样式适配，不搬移请求状态、Provider 或业务事件。
开发 Next.js 文件前阅读 node_modules/next/dist/docs 对应指南。

design:check 继续禁止任意 JSX 颜色、内联样式与固定大宽度；把 warm 专属提示
调整为中性语义 Token。检查工具通过不能替代屏幕渲染和状态验收。

Token 修改会全局生效：阶段划分用于开发验收，不把半套新旧 UI 分批上线。
不建立长期双主题或运行时开关；保留旧提交和完整部署作为回滚基线。

## 9. 验收矩阵

| 范围 | 必须验证 |
| --- | --- |
| 390/768/1440px | 无横向溢出；输入与参数不遮挡；手机键盘、抽屉、长标题、横竖屏布局 |
| 视觉 | 旧奶油/珊瑚/衬线清理；Logo 比例和品牌色；浅/深底对比；所有关键状态一致 |
| Home | 三模式、模板进入 Agent、游客登录草稿恢复、页脚显隐 |
| 导航 | 侧栏展开/收起；最近会话折叠、新建、改名、删除；前进/后退 |
| Agent | 追问、报价、确认/失效/额度耗尽、结果、部分失败、会话恢复 |
| 工作台 | Image/Video/Assets 切换保留草稿/附件/请求；参数和积分清晰 |
| 媒体 | 横竖图/四图、预览、播放/静音、Reference、Reprompt、下载和删除 |
| 付费/账号 | Pricing 保留草稿；价格/周期；升级/降级/删号确认与错误反馈 |
| 键盘 | Tab/Shift+Tab/Escape、可见焦点、嵌套 Modal、关闭后焦点回归 |
| 数据与事件 | 无接口契约改动；原有 GA4 触发与去重；不采集私有消息和素材 URL |

每批 UI 改动运行 design:check 并检查手机/桌面；最终运行 npm run test、
npm run lint、npm run build、npm run design:check。对有交互调整风险的部分
补有意义的行为验证，不用 CSS 类字符串断言代替视觉检查。

fixtures 可覆盖界面状态；真实 Google 登录、Qwen/媒体、Blob、Stripe、退款及
生产 Analytics 仍按授权环境和预算验收，必须分别标注证据，不能把模拟通过视为真实通过。

## 10. 风险、发布与交付物

主要风险：

- 全局 Token 改动遗漏深色控件、旧样式覆盖：全站组件和状态盘点。
- 字体/胶囊引发手机换行、遮挡：长文本、参数和价格专项验收。
- 修改组件层级造成草稿/请求丢失：保留 key、状态所有者和挂载身份。
- 弹窗视觉调整破坏焦点或滚动：保留原生 dialog 行为并测试嵌套/跨断点。
- 品牌点缀过量或对比不足：Logo 并排校色、实际色组合测量、状态图标与文字兜底。

交付物：统一设计规范、Token 与基础组件、全站适配、组件展示页、响应式及状态
验收记录、实际测试结果、更新后的工程记录、可回滚提交/部署标识。

用户明确批准生产发布后才部署；完成标准为部署 READY + smoke:prod + 关键
页面视觉抽查。出现阻断生成/报价/导航或严重布局回归时，按授权回滚到完整旧版，
不临时恢复某一组 Token 造成混合风格。

本轮交付仅方案和文档同步；尚未更改 UI、依赖、API、运行配置或部署。
