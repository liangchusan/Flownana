# Flownana 设计系统

状态：Runway × Flownana 基线（2026-09-12 已获开发授权）
视觉方向：Runway 的黑白灰媒体感，Flownana 蓝黄品牌点缀
参考：[getdesign.md 的 Runway 分析](https://getdesign.md/runwayml/design-md)

本文档是人类和 AI 开发工具共同遵循的视觉与交互事实来源。参考内容只
用于理解公开可观察的设计规律，不得复制 Runway 的名称、标志或专有资产。
必须保留 Flownana 品牌、以媒体为中心的产品结构和转化漏斗。

## 1. 产品感受

Flownana 应当清晰、可信、安静而有能力，像经过认真设计的创作工作台，
而不是通用 AI 仪表盘。

视觉基线：

- 使用纸白画布、黑色主操作和中性灰表面
- 使用深色文字与单一 Inter 无衬线字体
- 蓝色承担焦点、链接和已有选中反馈；黄色只作品牌点缀
- 保留蓝黄 Logo 与海面生成动画作为稳定识别点
- 依靠表面色和留白建立层级，避免厚重阴影
- 生成媒体始终是页面视觉中心

## 2. 规范优先级

当不同来源冲突时，依次遵循：

1. `docs/PRODUCT.md` 中当前产品范围和验收标准
2. 本文档 `docs/DESIGN.md`
3. `MEMORY.md` 中当前实现约束
4. `components/ui/` 中已有基础组件
5. `components/blocks/` 中已有业务组件
6. 最接近的现有页面模式

未经明确批准，不得因为提示词、截图或生成代码而引入一套新的视觉语言。

## 3. Token

实现 Token 位于 `app/globals.css`，并通过 `tailwind.config.ts` 暴露。
UI 代码必须优先使用语义化 Tailwind 类，避免重复写原始颜色值。

### 颜色角色

| 角色 | Tailwind 用法 | 值 | 用途 |
| --- | --- | --- | --- |
| 画布/卡片 | `bg-background` / `bg-card` | `#ffffff` | 页面、卡片和浮层 |
| 主文字 | `text-foreground` | `#111111` | 标题和主要文字 |
| 正文 | `text-text-secondary` | `#404040` | 长文本和辅助说明 |
| 弱化文字 | `text-muted-foreground` | `#666666` | 标签、说明和元数据 |
| 柔和表面 | `bg-surface-soft` | `#f7f7f7` | 侧栏、区块和 Hover |
| 强调表面 | `bg-surface-strong` | `#eeeeee` | 中性选中和次级控件 |
| 细边框 | `border-border` | `#e5e5e5` | 分隔线和弱轮廓 |
| 输入边框 | `border-input` | `#8a8a8a` | 需要独立辨识的输入 |
| 主操作 | `bg-primary` | `#111111` | 当前区域最高优先级 CTA |
| 主操作按下 | `bg-primary-active` | `#2b2b2b` | Hover 和按下状态 |
| 品牌蓝 | `text-brand-blue` / `ring-ring` | `#0066cc` | 链接、焦点、素材选中 |
| 品牌蓝浅底 | `bg-brand-blue-soft` | `#edf5ff` | 蓝色状态的辅助背景 |
| 品牌黄 | `bg-brand-yellow` | `#f5c542` | 少量品牌图形点缀 |
| 品牌黄浅底 | `bg-brand-yellow-soft` | `#fff8db` | 少量品牌引导底色 |
| 深色表面 | `bg-surface-dark` | `#1a1a1a` | 媒体框架、预览和页脚 |
| 深色浮层 | `bg-surface-elevated` | `#292929` | 深色表面中的控件 |
| 危险 | `text-destructive` | `#b42318` | 错误和破坏性操作 |
| 成功 | `text-success` | `#18794e` | 成功或可用状态 |
| 警告 | `text-warning` | `#8a5a00` | 警告状态 |

规则：

- 优先使用语义角色；旧 Stone/Zinc 仅作为迁移兼容，不新增原始色系。
- 禁止在 JSX 类名中加入任意 Hex 色；需要新角色时先批准并扩展 Token。
- 黑色用于主 CTA，品牌蓝不替代所有主按钮。
- 黄色上只使用深色文字，不能兼任警告、成功或推荐套餐语义。
- 深色表面用于承载媒体或高对比产品时刻，不是默认页面背景。

### 字体层级

| 角色 | 类 | 用途 |
| --- | --- | --- |
| 超大展示 | `font-display text-5xl md:text-display-xl font-medium` | 仅落地页 Hero |
| 大展示 | `font-display text-4xl md:text-display-lg font-medium` | 主要营销区标题 |
| 中展示 | `font-display text-3xl md:text-display-md font-medium` | 页面和工作台标题 |
| 小展示 | `font-display text-display-sm font-medium` | 卡片和提示标题 |
| UI 标题 | `font-sans text-lg font-medium` | 功能面板和弹窗 |
| 正文 | `font-sans text-base leading-relaxed` | 默认阅读文字 |
| 小正文 | `font-sans text-sm leading-relaxed` | 辅助文字 |
| 标签 | `font-sans text-sm font-medium` | 输入和控件 |
| 说明 | `font-sans text-xs font-medium` | 元数据和细则 |
| 代码 | `font-mono text-sm` | 仅技术内容 |

展示与正文均使用 `Inter`，中文使用系统无衬线回退；`font-display` 仅表达
排版层级，不再切换到衬线字体。Logo 保留品牌资产自己的字形。

### 形状、间距与层次

- 基础间距单位为 4px，优先使用 Tailwind 的 2/3/4/6/8/12/16/24 档位。
- 页面容器：`mx-auto w-full max-w-7xl px-4 sm:px-6 lg:px-8`。
- 营销区垂直节奏：`py-16 md:py-24`。
- 工作台面板：桌面 24–32px，移动端 16–20px 内边距。
- 标准控件使用 `rounded-ui`（8px）。
- 内容卡片使用 `rounded-ui-lg`（12px）。
- 大型媒体和 Hero 框架使用 `rounded-ui-xl`（16px）。
- 主/次按钮使用胶囊；圆形图标按钮继续使用 `rounded-full`。
- 默认不使用阴影；Hover 分离用 `shadow-soft`，弹窗或浮层才用 `shadow-float`。

## 4. 核心组件约定

### 品牌 Logo

2026-09-10 用户批准使用提供的蓝色波浪与黄色香蕉 Logo。浅色区域使用完整
横版标识；深色区域保留彩色图标，品牌字形以白色显示。图标和文字保持原始比例，
统一复用 `components/ui/logo.tsx`；标签页、Apple 主屏幕和生成等待动画使用
独立图标。该品牌资产替换不改变页面配色、导航或其他设计 Token。
Home 与创作工作台的侧栏、移动顶部和抽屉使用 96px 宽的紧凑横版 Logo，
按原比例显示，高度约 21.5px。桌面展开侧栏与手机抽屉宽 260px，桌面收起宽 64px。

创建交互基础组件前必须先搜索 `components/ui/`。优先扩展已有组件变体，
不要复制标记结构。

### 按钮

- 主按钮：黑色背景、白字、胶囊、标准高度 40px。
- 次按钮：白色画布、中性边框、深色文字。
- Ghost：默认透明，Hover 时显示表面变化。
- 破坏性按钮只使用语义危险色。
- 所有变体都必须有 focus、disabled、hover 和 active 状态。
- 每张卡片、面板或一个视口区域只保留一个主操作。

### 输入框和文本域

- 使用白色表面、可辨识边框和 8px 圆角。
- Focus 使用品牌蓝语义焦点环，不得移除焦点提示。
- 标签始终显示在控件上方；Placeholder 只能作为示例，不能替代标签。
- 校验文案必须说明发生了什么以及如何继续。

### 卡片

- 编辑式/营销卡片：`bg-card`，通常无边框、无阴影。
- 功能卡片：`bg-background border border-border`。
- 深色媒体卡片：`bg-surface-dark text-background`。
- 避免嵌套超过两层可见卡片表面。

### 导航和标签页

- 导航保持安静；选中状态使用表面色和文字色，不到处使用亮色实心胶囊。
- 桌面头部高度 64px，移动端控件最小触控区域 44px。
- 标签页同时使用表面和文字颜色变化表达选中状态。

### 生成媒体

- 结果是创建页和历史页的视觉中心。
- 使用不会给媒体偏色的中性或深色框架。
- 始终保留宽高比，不得拉伸生成媒体。
- 操作应贴近结果，但不能遮挡重要内容。

### 全局媒体预览

- 快速预览统一使用 `MediaPreviewModal`：`bg-surface-dark/95` 全视口遮罩，媒体居中，图片/视频使用 `object-contain`，视口内边距 16px，桌面最大宽度 80rem。
- 右上角关闭按钮统一为 44px 圆形 Ghost 控件，使用 Lucide `X`，必须提供 hover、focus-visible 和 active 状态；点击遮罩空白区域与 `Esc` 均关闭。
- 图片与视频预览都保留原始比例；视频统一使用原生 controls、`autoPlay`、`playsInline`，不由预览层强制静音。打开预览时禁止页面滚动，关闭后恢复触发媒体卡片的焦点。
- My Creations 可使用详情变体承载 Prompt、参数和媒体操作，但遮罩、关闭、键盘、滚动和媒体尺寸必须与快速预览一致；详情信息不得改变媒体比例或遮挡媒体主体。

## 5. 页面模板

### 首页与公共信息页

- `/` 保留共用侧栏；首屏以 “What will you create today?” 和完整 Image/Video
  输入组件为中心，下方展示 16 个图片 Templates。移除 Featured capabilities、
  文字示例和最近作品。Home 菜单向下展开并限制高度，工作台底部菜单保持向上展开。
- Home 手机/平板顶栏不显示居中 Logo，保留菜单入口；侧栏和公司页脚 Logo 保留。
- 原营销首页的 Hero、功能介绍、用户评价、FAQ 和最终 CTA 不再展示。
- 仅未登录时在主内容滚动区域底部展示公司页脚；使用与生成区相同的 `bg-background`、
  `text-muted-foreground`、`text-foreground` 和 `border-border`，与 Home 协调，
  不使用黑色背景。桌面不覆盖侧栏，移动端单列；已登录或 Session 加载中不展示。
- 隐私政策和服务条款保留正文，仅提供简洁 Logo 和返回首页入口，无营销顶栏
  和公司页脚。其他页面的既有页脚样式不变。
- 账户菜单新增 Pricing、Contact Us 和两个法律入口，顺序以 PRODUCT 为准；
  保留桌面浮层和移动端底部 Sheet，菜单过高时可滚动，触控入口至少 44px。

### 创作工作台

1. 全局顶栏
2. 紧凑创作导航
3. 参数/输入区域
4. 包含空、生成中、成功和失败状态的结果区域

移动端面板纵向排列，桌面可拆分多栏。允许功能密度，但必须保持温暖、
安静的整体感受。

### 定价页

- 移动端一列，桌面最多三列。
- 默认卡片使用画布和细边框。
- 推荐套餐使用轻量灰底或深色表面中的一种，不叠加品牌色装饰。
- 价格、周期、积分、CTA 和降级限制必须易于扫读。

### 登录、空、加载和错误状态

- 使用与主流程相同的画布、字体、控件和间距 Token。
- Skeleton 几何形状应与最终布局一致。
- 空状态应引导到下一步最有用的操作。
- 错误信息必须直接且可操作；红色只在语义需要时使用。

## 6. 响应式与可访问性底线

- 从移动端开始，在 `sm`、`md` 和 `lg` 逐步增强。
- 禁止 `w-[800px]` 等固定内容宽度，使用 `w-full` 与 `max-w-*`。
- 所有控件必须可用键盘操作并显示 `focus-visible`。
- 正文和控件保持 WCAG AA 对比度。
- 非必要动画尊重 `prefers-reduced-motion`。
- 核心触控操作在空间允许时至少 44px 高。
- 至少检查 390px、768px 和 1440px 三种宽度。

## 7. 动效

- 默认交互：`transition-all duration-300`。
- 布局稳定时可用 `active:scale-[0.98]` 提供按压反馈。
- 与其使用大量环境动画，不如只保留一个有组织的关键动效。
- 动画不得延迟生成反馈，也不得遮挡加载或错误状态。

## 8. AI 实现与验收清单

开发前：

1. 阅读 `AGENTS.md`、`docs/PRODUCT.md`、`MEMORY.md` 和本文档。
2. 找到最接近的现有页面、业务块和基础组件。
3. 明确复用哪些现有组件。
4. 判断是否属于需要先更新产品文档的大功能。

完成前：

1. 运行 `npm run design:check`。
2. 运行 `docs/PRODUCT.md` 针对本次风险要求的验收检查。
3. 至少在 390px 和 1440px 检查改动页面。
4. 检查本次涉及的空、加载、成功、错误、hover、focus 和 disabled 状态。
5. 失败项必须记录页面、状态、视口、原因和修复结果。
6. 产品行为或设计决策变化时更新 `docs/PRODUCT.md`；实现或运行状态变化时
   更新 `MEMORY.md`。

## 9. 禁止的捷径

- 复制 Runway 名称、标志或专有资产
- 已有基础组件可用时重新创建原始按钮、输入框或卡片
- 把 Slate/Gray、紫色 AI 渐变、厚重黑影或玻璃拟态作为默认风格
- 在 JSX 中加入任意颜色、内联 `style={{}}` 或桌面固定大宽度
- 整体复制通用聊天产品；Create 可以使用右对齐提示词和响应层级，但必须
  保持 Flownana 品牌、媒体优先，且不得虚构 Agent 执行过程 UI
- 未检查真实渲染结果就声称视觉工作完成

## Home 模板卡片（2026-09-11）

- 图片比例 4:5，桌面 6 列，平板 4 列、小屏 3 列、手机 2 列，间距 12px。
- 名称叠加图片左下角，底部深色渐隐保障可读性；移除卡片外文案和模块副标题。


## Agent 会话交互（2026-09-11 确认，已进入实现）

以 PRODUCT 第 18 节为准；本节为下一版设计要求，不代表界面已经实现。

- 首页输入模式增加 Agent，与 Image/Video 并列；Agent 隐藏后置模型和参数选择器；上传按钮沿用 Image/Video 的圆形“+”。
- 首页首次发送 Agent 需求进入独立会话；模板卡片点击直接进入带模板背景和简短
  输入引导的会话，取消模板弹窗。模板长 instruction 不作为默认编辑表单。
- 侧栏不设置独立 Agent 标签入口，保留会话记录及新建、重命名、删除能力；移动端沿用抽屉导航。
- 中央内容流承载用户需求、参考素材、Agent 回复、可点击回答选项、确认卡片和
  图片/视频结果；底部输入支持继续交流。沿用现有品牌与媒体优先的视觉规范。
- 参数通过自然语言表达，生成前确认卡片清楚呈现实际模型、数量、规格与总积分，
  保留明确的付费主操作；修改需求后旧报价不可继续提交。
- 生成和选图编辑留在当前会话；图片转视频也在同一会话中逐次确认。只展示真实
  执行状态，不虚构思考、工具调用或工作进展。
- 复用现有媒体预览与下载能力，保证手机单列和桌面内容可读；后续实现检查
  390/768/1440px，覆盖空会话、加载、追问、待确认、生成中、成功与失败状态。

### 2026-09-16 对话、选择与结果统一规则

- 用户消息统一右对齐，使用与 Create 结果流一致的紧凑圆角气泡；附图统一在文字上方，
  使用 Image/Video Composer 的紧凑参考缩略图。Agent 文本、提问和系统状态保持左侧
  阅读流，不使用模拟“思考中”内容；回复准备中仅显示加载状态，不显示 Stop reply。
- 单选快捷回答是可执行动作：按钮文本应是完整可读答案，点击即发送并在时间线出现
  右侧用户消息；按钮需有 hover、active、focus 和发送中的 disabled 状态。自由输入
  始终可用。多选场景必须把临时勾选与“确认选择”分开。
- Agent 图片报价默认 4 images，四张共用相同优化 Prompt、素材和参数；不显示多个
  方向或不同 Prompt。当前有效报价先以“已为你准备好需求概括生成方案，点击
  Generate 即可生成。”表达 Agent 已理解需求；模型和参数不在该反馈中重复。
- 当前有效报价不显示“Ready to generate”标题，也不使用 Prompt 外框套卡片外框；优化
  Prompt 使用轻量柔和输入面，下方复用普通创作的模型/参数入口。参数面板优先向下，若
  可视区域不足则自动向上展开并限制在可用高度内。修改即时且无感地更新按钮上的积分；
  卡片不另列总价。参数入口与 `N credits + Send` 主操作在同一行。唯一付费动作使用与
  Image/Video 相同的 `N credits + Send` 图标，重新
  报价未完成时该按钮禁用。旧/已提交报价不显示状态标题、查看详情或失效提示，仅
  保留必要 Prompt 摘要，避免同一方案在时间线重复占据高度。
- Agent 图片卡不得强制 `aspect-square` 或以黑底填充非方图；按媒体原始比例在可用最大
  尺寸内呈现。视频复用普通工作台的悬停播放、进度、音量和全屏预览组件。图片和视频
  点击媒体本身均打开统一预览，下载入口位置、尺寸和可访问性与普通结果一致。
- 图片右上角操作保留 `@` Reference、Download 和 Delete；`@` 将图片作为参考素材预填
  到底部 Composer，不自动发送。Agent 结果暂不显示 Edit image 或 Make video。
- Agent Composer 添加的素材默认是普通 Reference，不显示用途标签或下拉选择；用户以
  对话文字表达素材用途。只有参考素材时也可发送，消息发送成功后清空 Composer 的 Prompt
  和全部临时参考素材。
