## 1. 目标与推荐范围

桌面点击登录后在独立的 Google 授权小窗口选择账号，Flownana 原页面保持当前
URL、Prompt、参数和可恢复素材。成功后原页面更新账号和积分，正常情况下无需整页刷新。

推荐首版边界：

| 场景 | 处理 |
| --- | --- |
| 桌面 Chrome、Edge、Safari、Firefox | 默认独立弹窗，建议约 520×680，尺寸/位置由浏览器最终决定 |
| 手机浏览器 | 首版保留现有同页跳转及草稿恢复；手机弹窗/新标签体验不列入首版承诺 |
| 浏览器明确拒绝创建弹窗 | 使用原有同页登录兜底，保留原页面返回地址与草稿 |
| 用户主动关闭/取消 | 留在原页，不自动改用整页跳转，恢复登录入口以便重试 |
| OAuth 成功但窗口间联系中断 | 原页重新读取服务端会话确认；不能仅凭窗口消息认定成功 |
| Google 拒绝应用内浏览器 | 提示使用系统浏览器，不进行重复跳转循环 |

登录完成不自动发起媒体生成、付款或重复提交。Pricing 保留所选套餐/周期，仍由
用户再次点击继续购买；已有免费/付费权益不变。失败或取消不能清空创作草稿。

## 2. 技术选型

推荐复用当前 NextAuth v4 + Google OAuth 授权码流程，把授权导航放在子窗口中。
沿用现有 Google provider、账号 ID、JWT Session、CSRF、state、PKCE、注册赠送及
统计许可回调。首版不新增 One Tap，不切换身份提供方，不另做一条 ID token 注册链路。

Google 官方 GIS 也提供 popup 模式，但直接切换 GIS 会涉及凭据验证及会话接入；
本方案优先复用已有回调路径。当前 NextAuth v4 的 Google OAuth 不能只靠
`signIn(..., { redirect: false })` 改为弹窗，因此需要同源启动/完成页与主窗口协调。

Google 的 OAuth redirect_uri 继续为已有 `/api/auth/callback/google`；
新增的同源完成页属于应用内部 callbackUrl。预计无需更换 Google Client ID 或新增
Google 回调地址，开发时仍应核对实际配置。方案不需要数据库迁移或新增平台密钥。

## 3. 正常流程

1. 从所有入口统一进入现有公共登录层，先固定返回目标、账号范围及草稿，并创建
   仅用于本次操作的随机 attempt ID。在点击处理的同步阶段立即打开同源启动页，
   避免等待网络后丢失用户开窗许可；重复点击复用本标签页正在进行的操作。
2. 原页执行现有统计准备，仍最多 6 秒、暂时失败最多重试 3 次。窗口中只显示
   简短的“正在准备登录”；准备失败/拒绝/GPC 继续登录，不伪造允许状态。
3. 准备结束后启动页调用现有 NextAuth Google signIn，仅子窗口导航到 Google，
   应用内部 callbackUrl 指向 `/auth/popup-complete`。主窗口不调用会导致自身跳转的
   OAuth signIn。启动消息校验精确同源、来源窗口及 attempt ID，只受理一次。
4. Google 仍显示其官方账号选择/授权页面。NextAuth 原回调在服务端验证并建立会话，
   继续执行真实新账号创建、注册赠送资格及 sign_up 的现有逻辑。
5. 同源完成页确认会话后向原页发送不含身份凭据的完成通知。原页再次获取服务端
   Session，以该结果刷新账号范围、余额和相关受保护数据；消息本身不能建立会话。
6. 在账号状态已确认后，原页完成匿名草稿承接并恢复焦点；正常情况下子窗口自动关闭。
   如浏览器不允许自动关闭，子窗口显示“登录成功，可以关闭此窗口”。

## 4. 操作状态与恢复

公共登录层明确区分：空闲、准备中、等待 Google、核对登录状态、完成、取消、失败。
只在相关登录入口显示等待状态，原页不加遮罩锁住全部创作区；按钮继续展示原有文案
或积分，使用 loading/disabled 状态防止重复发起。已有进行中的生成任务继续工作。

- 同一标签页同时最多一个登录操作。重复点击尝试聚焦已打开窗口，不再创建新窗口
  或重复发起 OAuth；登录准备期间选择 Pricing 可以更新返回意图，成功仍不自动付款。
- 原页在等待期间允许用户继续编辑，恢复时保留最新草稿，不用开窗时的旧快照覆盖。
- 正常会话变化必须走已有账号版本/取消机制。匿名到首次登录可承接匿名草稿；从旧
  账号切到另一账号不能携带旧账号素材、缓存、Agent 草稿、待请求或 Pricing 归属。
- 整个窗口等待最多 3 分钟。收到有效通知或原页重新聚焦时立即核对 Session；必要
  兜底检查最多每 5 秒一次，原页隐藏时暂停。超时释放监听和定时器，保留草稿并允许
  重试/选择同页登录；超时不撤销已经成立的真实会话。
- `window.closed` 只能是恢复线索。COOP 可能让仍打开的窗口报告 closed，不能据此
  自动跳转、重复登录或宣布用户取消；先核对会话，异常时提供明确的重试路径。
- popup 消息失联时可用 BroadcastChannel 发送同源“请核对会话”提示，仍须由原页
  获取真实 Session。每个标签页/操作使用独立随机名称，避免跨标签复用对方窗口。
- 不承诺两次跨标签页 OAuth 并发都成功；检测到在途登录时优先等待既有结果。
  若极端竞争造成 state/PKCE 冲突，应明确失败并重试，不能绕过校验或登录错误账号。
- 原页刷新后，只恢复短期等待描述并核对真实会话，不自动新开窗口或重放原操作。
  原页关闭后，子窗口可完成登录并提示返回 Flownana；不承诺恢复已关闭标签页的内存内容。
- 完成后迟到的消息/轮询结果须匹配当前操作，不能覆盖后续账号状态；所有终止状态
  清理监听、定时器和短期操作描述，之后首次/再次打开行为一致。

## 5. 安全、统计与赠送保持

- 继续复用现有 OAuth CSRF/state/PKCE、服务端账号身份及 HttpOnly 会话 Cookie；
  不把 Token、授权码、邮箱、账号 ID 或素材写入跨窗口消息、可分享 URL 或日志。
  随机 attempt ID 仅关联 UI 操作，不是认证凭据，不授予账号权限。
- 通知只含固定类型、操作 ID 和有限结果码。postMessage 使用精确 targetOrigin，
  接收方校验 origin、source 和操作 ID；无法验证的消息丢弃，采用真实会话核对。
  不读取 Google 页面内容，不向非同源页面发送业务数据；不允许任意 returnTo/外站跳转。
- 辅助页不展示导航、创作区、Pricing、营销内容或额外统计许可面板；不初始化
  Google 衡量标签，不上报 page_view，也不把 attempt ID 写入 GA。Google token/code
  仍只由现有回调处理，不增加公开调试/登录模拟端点。
- 登录前统计准备在原页执行，保留已批准的公共 UTM 承接与必要禁止 Cookie。
  用户在 Google 窗口打开后撤回/GPC/切换地区，真实回调仍按当前证据重新校验，
  不信任开窗前的允许快照。隐私拒绝不能阻断登录或合格的新账号赠送。
- 继续仅六个 GA4 事件：sign_up 以真实新建事实去重；不因 popup 启动/结束/关闭
  新增 sign_up，不补发历史缺失来源，不扩大广告许可。
- 10 积分、七地区白名单、同 IP 72 小时、30 天到期及回调幂等保持不变；
  资格仍取现有真实服务端 Google 回调请求，不使用父窗口自报 IP/地区。
- 如兼容测试发现 COOP/CSP 必须调整，先证明具体阻断原因，并将改动限制到必要
  路由；不以全站移除安全头作为默认解决方式。
